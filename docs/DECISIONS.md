# Decisions

Phase 1 decisions and why. Newest at the bottom.

1. **Next.js 15.5 rather than 16.**
   - Auth.js v5 and the middleware pattern are proven on 15.
   - Moving to 16 is a contained upgrade for later.
2. **Rating levels stored as 1 = Outstanding … 6 = Very Weak.** This matches the form's column order and UAE
   inspection convention. Lower is better.
3. **Rounding.**
   - Area judgement = mean of the rated criteria in the area. Overall = mean of the areas' effective levels
     (after any override).
   - An exact .5 rounds towards the weaker level (agreed with the product owner).
4. **Overrides keep the computed value.** The override and its required reason are stored separately
   (`area_judgements`, `observations.overall_override_*`). The computed mean is always recalculated, never
   stored, so it can't go stale.
5. **Visit status is derived, not stored.**
   - No observation row: Not started. Draft: In progress. Complete: Complete.
   - The observation row is created on the first save, not on opening the form.
6. **Offline tolerance.**
   - Every change is an op carrying the time it was made on the device.
   - Ops are kept in localStorage until the server confirms them, retried with backoff, and sent with
     `sendBeacon` when the page is hidden.
   - The server applies last-writer-wins per field (rating, comment, header field, override), so resending is
     always safe and late arrivals never overwrite newer edits.
   - Opening the page with no signal at all needs an offline app shell, which is on the Proposed list.
7. **`users` and `teachers` are separate tables.**
   - Team leaders on the schedule (Ms. Asmaa Aly, Ms. Cornelia and others) are teachers, not observer logins.
   - Their 14 visits are seeded with the observer's name as text, so the register is complete. Only admin sees
     them.
8. **Access rules are enforced on the server, on every request.**
   - Role and password state are read from the database, not trusted from the session cookie.
   - Observers can open and save only their own visits; another observer's visit returns 404.
   - Admin can read every observation and edits only visits assigned to them.
   - Teachers cannot reach the form, the admin page or export.
9. **Signature line wording kept exactly as on the form ("MYP Coordinator…")**, at the product owner's request,
   though ASAD is PYP.
10. **Grade bands.** KG classes are KG; Grades 1–2 are Lower Primary; Grades 3–5 are Upper Primary. This is
    editable in Phase 4.
11. **Usernames.**
    - Usernames are first names in lower case, with a dot before a second name (`asmaa.aly`, `fatma.hassan`).
    - The admin's username is `admin`, shown as "Administrator". No personal name or email appears in the app.
    - Temporary passwords are never stored in the repository.
12. **"Title" header field** is kept as free text exactly as on the form. Its meaning (observer title or lesson
    title) is left to the observers.
13. **Required before Mark complete:**
    - Every header box except Title.
    - All 20 criteria rated.
    - A reason for every override.
    - Number present no more than number on roll.
14. **Percentage key helper is a suggestion only.**
    - It reads the counts against the form's descriptors and key.
    - The form leaves 16–49% between "Weak" and "Very Weak" for Attainment and Progress. The helper suggests
      Weak there and the observer decides.
    - The counts are not saved.
15. **Previous observation peek.**
    - Shows another observer's area levels, which the school dashboard will show anyway.
    - Shows comments only to their author and admin.
16. **Tours** are recorded per user in `users.tours_completed`, so each tour starts by itself once, on any device.
17. **Export is built on the server per role.**
    - The Excel workbook is built with exceljs.
    - The CSV includes a byte-order mark so Excel reads Arabic names correctly, and neutralises formula-like
      text.
    - Password hashes are never exported.
18. **Migrations.**
    - Generated by drizzle-kit.
    - Applied by `scripts/migrate.ts`, which runs on Vercel production builds (`vercel-build`) and is skipped
      for preview builds, so previews never touch the production database.
19. **Testing never touches live data.** End-to-end checks run against a throwaway Neon branch of the
    production database, never the production branch.
20. **Known advisories.**
    - `postcss` (bundled with Next 15) only affects processing untrusted CSS, which this app never does.
    - `uuid` is overridden to 11.x for exceljs.
21. **No email.**
    - The school uses its own registered mail, so this system sends none.
    - Sharing, invitations, introductions and the Friday summary all arrive as in-app notifications.
    - Feedback can still be copied or downloaded as a PDF.
22. **AI model and guard rails.**
    - Claude Sonnet 5.5, structured output, medium effort, with the server-side refusal fallback.
    - The server checks the school's rules (line counts, word count, opening, closing, no dashes) and retries once.
      Anything still off is shown to the observer, never silently "fixed".
    - At least 10 rated criteria are needed before a draft.
23. **Demo data lives in the same database, marked `is_demo`** (on cycles, workshops, pairings, notifications and
    digests).
    - Everything under a demo cycle is removed by cascade on Go live.
    - Demo sessions are only valid before Go live, and password sessions only after it.
24. **Demo uses real staff names** at the product owner's request. Every demo page carries a "Sample ratings, not
    real judgements" banner, and every demo PDF a matching label.
25. **Experts, support and pairing rules.**
    - Expert = area level Very Good or Outstanding. Needing support = Acceptable or below.
    - Both use each teacher's latest completed observation in the current filter.
    - Workshop suggestions cover the three weakest areas that have at least one teacher needing support.
26. **Workshop effect.** Area level in the last observation before the workshop compared with the first observation
    after it, for attendees marked present.
27. **Reopening.** Reopening a completed observation withdraws it from the teacher and clears the coordinator
    signature. Once the teacher has signed, it can no longer be reopened.
28. **Observers who are also observed** (for example a team leader promoted to observer) keep a "My own
    observations" page.
29. **Arabic.** The teacher-facing feedback is translated on demand by the same model and cached until the English
    changes. The rubric wording is never translated.
30. **PDF** uses the built-in Helvetica for reliable print. Hyphenation is disabled so descriptor wording reads
    exactly as on the form.
31. **Coordinators.**
    - The observer role is the coordinator role: full management access, but each coordinator edits only their own
      observations.
    - The admin login alone can Go live, Reset the demo, and reset the admin's own password.
32. **Team leader observations (formerly "peer observations") are a separate table** (`peer_observations`, with the original in `peer_files`), so they
    can never mix with official data.
    - The AI reads the form without guessing: unmarked or unclear rows are left unrated and flagged.
    - Names are matched to staff only when the match is unambiguous.
    - Only confirmed records count in the "how each team leader rates" comparison.
33. **Files.**
    - Originals are stored in the database: up to 4 MB each, and large photos are scaled down in the browser first.
    - Old .xls Excel files are not supported; save them as .xlsx.
